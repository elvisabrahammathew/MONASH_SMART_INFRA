# Initial data audit

The supplied archives should be treated as source data, not immediately model-ready tables.

## Observed structure

| Source | Structure | Implication |
| --- | --- | --- |
| `5occupancySensor_MayToDec2024_9MRows.zip` | One 1.6 GB CSV containing state observations with device ID, floor-space ID, occupancy status, headcount, and timestamp | Process it in chunks and filter to one mapped room before holding data in memory. |
| `5EnvSensor_MayToDec2024_180kRows.zip` | One CSV whose sensor values are nested in JSON | Extract and de-duplicate variable-time measurements before analysis. |
| `Sensor ID and Locations.xlsx` | Separate environmental and occupancy mapping sheets | Join only on documented IDs. Do not infer room co-location from similar labels. |

Environmental JSON contains battery, carbon dioxide, humidity, formaldehyde, pressure, temperature, light VOC, and particulate-matter measurements. Units appear in the JSON metadata and must be kept in the final data dictionary.

## Findings that affect the project

- The occupancy archive includes observations outside the period indicated in its filename. The pipeline filters the analysis to May-December 2024.
- The occupancy mapping sheet is labelled as containing incorrect floor-space data. Treat mapping quality as a limitation and retain its exact mapping row in the report appendix.
- Only G.20 and G.25 map directly from the supplied occupancy records to the workbook in the initial audit. The main code selects G.25 because its mapping is unique.
- The supplied environmental records do not contain a validated co-located environmental sensor mapping for G.25. Environmental variables are therefore excluded from the main model by default.
- The data support predictive validation against later sensor records. They do not independently validate occupancy-sensor accuracy against manual counts or prove energy savings.

## Required checks before interpreting results

1. Read `audit.json` and report raw-event count, coverage, longest gap, headcount range, and missing resampled bins.
2. Inspect the 15-minute series around the largest outage. Confirm the one-hour forward-fill limit does not create a misleading value.
3. Confirm no negative headcounts, duplicated timestamps, or timestamps outside the stated analysis period remain.
4. Use the chronological train/validation/test split generated by the pipeline. Do not randomise timestamps.
5. Report final-test results once only, after selecting the method from validation MAE.
6. Ask the teaching team whether the data can be redistributed in a private repository and whether they can provide the correct environmental-to-occupancy mapping.
